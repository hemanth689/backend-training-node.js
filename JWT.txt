-> A JSON Web Token (JWT) is a standard used to securely transmit information between a client and server.
-> It is commonly used to verify user's identities, authenticate them, and ensure safe communication between the two. 
-> JWTs are mainly used in web apps and APIs to protect against unauthorized access.
-> In JWT data will be stored in simple JSON format. To keep the data safe a token is signed cryptographically.
-> It making sure that No one can alter token. The signing can be done using cryptographic methods such as HMAC, RSA or ECDSA.
-> JWT works like:
    -> when user logins the client sends login credentials to the server.
    -> If credentials are valid, the server creates a JWT containing user data and signs it with a secret key.
    -> The JWT is sent back to the client and stored. (localstorage or cookie)
    -> For protected routes, the client includes the JWT in the Authorization header (Bearer Token).
    -> The server verifies the token, extracts user info, and processes the request if valid.
-> JWT Structure:
-> It consists of three parts separated by dots. Header. Payload. Signature
Header: 
    -> Contains metadata about the token, such as the algorithm used for signing.
    ex:
    {
        "alg": "HS256",             //Algorithms like HS256, RS256
        "typ": "JWT"                //token type always JWT
    }
Payload: 
    -> It contains the information about user also called as claim.
    -> And some additional information about issued data and expiry time of the token.
    ex:
    {
        "userId": 123,
        "role": "admin",
        "exp": 1672531199
    }
Signature: 
    -> It ensures the token’s integrity and authenticity.
    -> It is generated using Header, Payload and a secret key.
    ex:
    HMACSHA256(
        base64UrlEncode(header) + "." + base64UrlEncode(payload),
        secret
    )

-> After all the above steps a final JWT token is generated by joining Header, Payload and Signature with dot.
